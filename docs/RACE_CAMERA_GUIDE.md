# レース観戦カメラの制作メモ

## レースを一度だけ走らせる

実況、先頭追走、自動演出、決勝写真は同じ `buildRaceTimeline` を読む。途中の並びはその時点の `standingsAt`、確定着順は `crossings`、写真は勝者の通過時刻を使う。視点を切り替えても時計と出走表を引き継ぐ。プレビューで別の結果を抽選する操作は「再出走」と番組の変更だけにする。

## 実況から追走へ切った瞬間に場所が分かること

地域名、開催番号の時間帯、天候、序盤・中盤・終盤の区間を実際の出走データから取る。実況が使う時間帯別の地域画から遠景・中景・路面を採る。L3の縁石と土の位置は絵ごとに違うため、地域を増やしたら昼と夜の両方で採取位置を確認する。近くの目印は走路の外側に置き、カメラを回しても同じ地面に留まるようにする。

| 会場 | 走路外で読み取れる目印 |
| --- | --- |
| グランドクロック | 街の外縁にある丘と時計塔。向かいの直線からも塔との前後関係が続く |
| ルミナ、ミストレイク | 湖面と岸の高低差。ルミナは青い結晶、ミストレイクは低い岩と葦 |
| ヴェント峡谷 | 直線に沿う峡壁と風向旗。旋回すると手前の岩と奥の稜線に視差が出る |
| カルデラ、灼熱回廊、煉獄頂 | カルデラは主火口、回廊は溶岩が海へ流れる石橋、頂は火口を囲む祭壇と金の火輪。溶岩と噴気は走路外の斜面を流れる |
| リングロッソ、竜王圏 | リングロッソは赤い岩場と幟。竜王圏は双竜の王城、海食アーチ、藍と金の鱗紋旗 |
| ノッテムーンライト | 紫の結晶と山並み。開催番号の時間帯を維持する |
| ラパン祭典、白兎神域 | ラパンは町の祭灯。神域は白金の社殿、滝のある白い岩棚、雲海、兎紋の祭旗と灯籠 |

走路、沿道設備、全頭の位置、決勝線は `rcChaseCourse(race)` の中心線と横方向の距離から求める。狭路に入ると縁とレーンが一緒に狭まり、上り坂では影とカメラも一緒に上がる。混戦橋の欄干と橋脚は中盤の橋区間だけに置く。

## アップと決着で見直すところ

- 実況と解説の字幕は全視点で共通の表示を使う。ゴール後は写真直下に移して最後の一言を残す。角度を変えたときに発言を消したり最初から打ち直したりしない。
- 上空風路では実際の進行距離に沿って羽ばたいて上昇し、頂点から滑空して決勝線に向かう。橋と小回りでは低く飛ぶ。実況と追走で同じ高度を使い、影は地面に、名前とカメラは竜に追従させる。歓声は先頭交代と終盤入りに合わせる。
- 先頭交代では新しい先頭二頭の中点を追い、二頭の間隔に応じてカメラを引く。最内と最外で競う組み合わせも見る。
- 自動追走の一続きのカットでは撮影する側を保つ。抜き返すたびに左右を横断させず、重なる場面では少し上から撮る。手動へ切り替える角度はそのコマの実際のカメラ方位に合わせる。
- 竜名は投影した胴体のそばに置き、引き線で個体に結ぶ。縦画面でも二枚の札、順位表、長い実況と重なっていないかを実レースで確かめる。
- 屋外の斜面には原画の岩肌や草地を採る。空や遠山を地形に貼ると水平線が二重に見える。遠景は原画の端を重ねて一周させ、左右対称の稜線が現れないかを回り込みで見る。
- 両翼は本編の翼パーツから左右の肩に取り付け、同じ周期で動かし、翼端を少し遅らせる。翼のない竜は元の姿を守る。真横、斜め前、正面で片翼の消失、胴体との隙間、頭部の潰れを確かめる。
- 52頭それぞれに正面頭部の透過原画がある。出走竜の `images/dragons_front/<id>.webp` を入場時から読み込み、横顔と正面画を一つの頭部に投影する。RC_CHASE_EYES には胴パーツ上の瞳の位置と正面画の向かって左の瞳の位置を登録する。正面・斜めでは同じ角と瞳が動く様子を、一時停止したまま角度を変えて確認する。追加の竜は `RC_FRONT_HEADS` に本編の胴パーツ上の頭の中心、角先から顎までの高さ、正面原画上の鼻の高さを登録する。冠や炎を含め、斜め前から正面を通って反対側まで回し、目の高さ、首との継ぎ目、翼と角の前後関係を確かめる。
- 決勝写真を選んだらゴールの拡大演出を止め、写真の上端まで戻す。短い横画面でも鼻先、線、実況を同時に読めるかを確認する。確定後に巻き戻したときは着順欄を閉じる。
- ゴールでは進行方向に対する横から撮る。曲線の出口にも世界座標の固定カメラを置かず、その決勝線の接線と法線を使う。手前の岩、欄干、ゴール帯が鼻先を隠さないようにする。接戦の相手を含め、写真に全出走竜を描く。

発走前の実況中に、出走モデルを一頭ずつ準備する。追走へ切るときの引っかかりは、レースを新しく開き、初めて視点を切り替えた瞬間の録画で確かめる。

ポロの体形は元の横向き原画を基準にする。丸い頬と腰、紫の鱗、茶色い角、短い鼻、赤いリボンを残し、胴の厚みは横から見た腹線と正面から見た幅を別々に確かめる。尻尾の幅は尾パーツの付け根から先端までを見て決める。後ろ脚まで含んだ切り抜きや、尾羽のある個体もいる。

動きの検品では動画の収録fpsと実機の描画間隔を区別する。実時間を測るときは録画や仮想時計を止め、同じ番組・同じ先頭争い・同じ画角で比較する。

### 脚と地形の調整

新しい竜の脚は `RC_LEG_LANDMARKS` に腹の下端と前後の足先を登録する。後ろ足が尻尾パーツにまたがる個体は、胴と尻尾を合わせた原画で足先を取る。飛行中は腹に脚を寄せる。地上型は左右の後脚で順に蹴り、前脚で体重を受ける。四肢が路面を離れる局面も描く。歩幅は脚の長さから決め、接地中は胴が進んだ距離だけ足首を後ろへ送る。遊脚は膝を折って足先を持ち上げる。正面からも接地が読めるよう、肩の位置を保って肘から足裏にかけて踏み幅を広げる。前後脚とも足首の角度と爪先を独立に確認し、斜面の横から荷重がかかる足裏とその影を見比べる。正面をまたいだときは奥の脚が胸の中央から生えて見えないか、順位札が爪先を隠していないかも見る。

峡谷の近景はコースの脇から谷へ落とし、遠くの岩壁を望める場所を残す。湖面の映り込みにはその開催時刻の遠景を使い、角度と再生位置に追従させる。草木や岩の根元は斜面の座標から決める。確認するときは同じ番組の同じ時点と角度を揃え、原画の稜線が二重に浮かないか、走路に境界の切れ目がないかを見る。

### 実況の遠景と屋外の追走

実況の空と山並みは一枚の地域画の内側でパンする。近景には縁石の高さを合わせた L3 のループを使う。画像の境目を調べるときはカメラが動いている場面で、屋根、峰、対岸が途中で別の絵に飛ばないかを見る。

ミストレイクでは岩浜、岸の針葉樹と灯り、水面の像を同時に見る。反射用カメラは水位で反転させ、岸と灯りを同じワールド座標から描く。カルデラでは主火口の方位を固定し、足元の赤白の縁石と麓の溶岩流までつなぐ。両会場とも、翼のある竜と地上型が競る第2レースで実況から追走に切り替え、手動で角度を動かして検品する。

通常の屋外会場では、実況と同じ L1 の月・火口を一か所に置き、背面へ回ると L2 の対岸が現れる。ルミナとヴェントの吹き流しは実況と追走の同じ距離に立てる。中盤でカメラを回し、湖岸の水晶・石造回廊のアーチ・岩稜の風下側などが竜の手前に飛び出さないかを確認する。二頭の画角は胴と顔の輪郭、翼端、足首から爪先までを含めて決める。濃霧でも遠景が単色になっていないか、参照する原画と実走の両方で確かめる。

### 島の地形と祭礼

灼熱回廊・竜王圏・煉獄頂・白兎神域は各開催時刻の専用 L1 原画を使う。現地の地形を正面に、母地域を対岸に配し、カメラを一周させて継ぎ目と天頂を確かめる。白兎神域の走路用 L3 は青灰色の石に調整してある。実況席と追走では同じ進行地点に同じ紋の祭旗を置く。霧、噴気、滝は岸や岩棚に根元を置き、風で動いても竜の前を幕のように覆わないようにする。

## 本編での読み込みと解放

追走用の Three.js と描画スクリプトは `rcLoadChaseRuntime()` にまとめ、通常は投票確定後の待機画面で会場・出走竜の原画と並行して読む。動きを減らす設定では実況から始め、手動で先頭追走を選んだ時点で読み込む。追走を準備できないときもレースと実況は続く。

連戦の検品では結果画面まで進め、レースプレイヤーへの参照が解放されたことと、次戦の原画キャッシュに前戦だけの竜が残っていないことを確認する。縦画面では購入した竜の順位、二人の実況、カメラの操作列が映像と重ならないかも見る。

## 再確認の手順

1. `index.html?racePreview=race_vento_1` などから実レースを起動する。`&view=front` を付けると先頭追走の90度から始まる。画面下の番組選択で同じ地域の別の時間帯・天候にも切り替えられる。
2. 実況から追走へ切り、角度を左右に動かしながら沿道の目印と先頭二頭を確認する。夜霧、雨、狭路、最終大旋回、大外の竜が勝つ写真も見る。
3. 本編の通常進行と、プレビューの「着順を見る」の両方で決着まで進む。写真と実況を往復し、勝者、順位表、全頭の確定着順を照合する。
4. ゲームのHTTPサーバーを起動し、Playwrightを利用できる環境で `node tools/visual/check_race_cameras.cjs` を実行する。`BASE_URL` でサーバー、`PLAYWRIGHT_PATH` と `BROWSER_CHANNEL` でブラウザー環境を指定できる。引数なしで全番組、引数にレースIDを渡すと該当番組を検証する。
