# 竜スカウト：交渉を「ゲーム」に作り直す（土台再設計）

## なぜ作り直すか

ユーザー指摘：**「交渉術を選ぶというのがセンスないです。選ぶだけはマジでゲームじゃないです」**

旧実装は「しぐさを読む → 手札から正しい交渉術を選ぶ」の繰り返し。
これは**クイズ**であって**ゲーム**ではない。押す前に答えが決まっていて、
指の動きにも、間合いにも、意味が無い。上達するのは知識だけで、腕が上がらない。

ユーザーの要求：
> 様々なジャンルの面白い話を十字キー型ボタンから竜の動きに合わせて選ぶことで興味をひき、
> そのすきにタイミングゲームでダンスに持ち込むくらいのトリッキーさがあっていい

## 何を残し、何を捨てるか

**残す**（良い資産・作り直さない）
- 舞台の絵（遠征先の背景 × 竜のスプライト × 距離演出）
- 心情10種の語彙（`SCOUT_MOODS` のしぐさ文）
- ロケ段階の解放・旅費・手土産・探索（けはい探し）
- 成立／決裂の出口（`_scoutWin` / `_scoutLose`）と払い出し
- 伝承（断章）の解禁、交渉メモ

**捨てる**
- 手札から交渉術を選ぶ操作（`scoutHand` / `scoutResolve` を使う画面）
  ※ 関数自体は消さない（他から呼ばれても壊れないように残す）

## 新しい遊び

### フェーズ1「話しかけ」— 竜の向きを読んで、十字キーで話題を当てる

竜は**絶えず動く**。ふと空を見上げ、地面の匂いを嗅ぎ、左右に跳ねる。
その動いた方向が、いま竜の気が向いている方向。

画面下の**十字キー**の4方向に、それぞれ話題のジャンルが載る。

```
        ↑ そら
   ← うわさ  → たび
        ↓ ごはん
```

- 竜が向くと、その方向のボタンが光る＝**チャンス窓**が開く
- 窓が開いている間に**その方向**を押す → 刺さる。ミミが実際にその話を語り、興味が上がる
- 押し間違い／窓を逃す → 興味が下がり、警戒が上がる

**ここがゲームである理由**：正解が事前に決まっていない。竜の動きを見て、
間に合ううちに指を出す。読み・反応・度胸が要る。

### トリッキーさ（要求どおり入れる）

1. **フェイント**：向いた瞬間に戻ることがある。釣られて押すと空振り
   （竜の気まぐれ度 `persona.fickle` が高いほど多い）
2. **飽き**：同じジャンルを続けると効果が落ちる（3回目で半減）＝話題を散らす必要がある
3. **加速**：興味が上がるほど竜が興奮し、窓が短くなる（後半ほど難しい）
4. **好み**：竜ごとに好きなジャンルがある。刺さると特大。メモに残り、再訪で有利

### フェーズ2「ダンス」— 隙を突いてタイミングゲーム

興味が満ちると竜が体を揺らしはじめる。ここで**踊りに持ち込む**。

- 4方向のステップが流れてきて、判定ラインに重なった瞬間に同じ方向を押す
- **ピッタリ／おしい／ミス**の3段階判定
- 続けて決めると「ノリ」が伸び、竜が跳ねて踊る
- 規定ステップを踊り切って出来が閾値以上 → **成立**（仲間になる）
- 出来が低い → 竜が興ざめして去る（＝決裂）

**トリッキーさ**：終盤でテンポが上がる／竜がステップを1つ飛ばすフェイントを混ぜる

## 数値（すべて表示専用・レースの着順/オッズ/配当に非干渉）

| 値 | 範囲 | 意味 |
|---|---|---|
| 興味 | 0〜100 | 満ちるとダンスへ。`sess.trust` を流用 |
| 警戒 | 0〜100 | 満ちると逃走。`sess.wary` を流用 |
| ノリ | 連続数 | ダンスの採点。判定の重みづけに使う |

セッションの器（`createScoutSession`）と出口（win/lose）は既存のまま。
**中身の遊びだけを差し替える**ので、ロケ解放・払い出し・図鑑は一切触らない。

## 実装の置き場

| ファイル | 役割 |
|---|---|
| `js/data_scout_topics.js` | 話題4ジャンルと、ミミが語る台詞（新規・データのみ） |
| `js/scout_game.js` | 話しかけフェーズとダンスフェーズのループ（新規） |
| `js/ui_scout.js` | 手札の描画を、新しい画面の呼び出しに差し替え |
| `style.css` | 十字キー・ダンスの譜面・判定の見た目 |

**止まらない作りにすること**：画面を離れたらループを必ず止める
（`document.body.contains()` で自停止）。例外で固まったら成立も決裂もできなくなる。
