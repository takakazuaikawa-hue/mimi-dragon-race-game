# 🧱 UI土台工事の正本（2026-08-02 開始・第1弾＝角丸 完了）

## 結論：レイアウト・各ページのコンセプトを残したまま統一することは**可能**（実証済み）

ユーザーの問い＝「失敗すると今のデザインが崩壊する大改修。今のビジュアルと各ページの
コンセプトを残したまま統一するのは本当に可能か」。

答え＝可能。ただし条件つき：**「見た目が変わっていないこと」を毎回機械で証明しながら進める**。
第1弾（角丸759箇所中592箇所のトークン化）で方法そのものを実証した：

1. **見た目の指紋**（`tools/ui_snapshot_snippet.js`）＝18画面のDOM全要素について
   デザイン系の計算済みスタイル15種をハッシュ化。工事前に基準を取り、工事後に照合。
2. **A/Aテスト**＝何も変えずに2回測って18/18一致（計測器自体の信頼性を先に確認）。
3. **完全一致の置換だけ**＝値が同じものだけを var() へ寄せる（数学的に見た目が変わらない）。
   値を動かす統一（11px→12px等）は**見た目が変わる別工事**＝ユーザー決裁が要る。
4. 結果＝18/18一致で完了。しかも途中で**本物のバグを1件検出**した：
   既存トークン系（下記）と知らずに衝突し `--r-4` が 4px と 22px の二重定義になり、
   13箇所が22pxに化けた。ゲートが media 画面の差分で捕捉→合流して修正→再度18/18。
   **このゲートが無ければ「崩壊」がまさに起きていた**＝ユーザーの懸念は正しかった。

## 正本のトークン系＝「UI装飾第1波」ブロック（style.css 後方の :root）

2026-08-01 の第1波が既に設計していた系に**合流**する。並行の系を作らない（前科あり）。

| 種類 | トークン | 意味 |
|---|---|---|
| 角丸4段 | `--r-1:9px / --r-2:12px / --r-3:16px / --r-4:22px` | チップ/部品/カード/窓。**これ以外を増やさない** |
| 形状2種 | `--r-full:999px / --r-round:50%` | ピル形・正円（段ではなく形） |
| 移行トークン | `--rd-4/6/8/10/14/18` | 4段の外にある現状値の**仮の住所**。最終的に4段へ寄せて消す（値を動かすのでユーザー決裁つき） |
| 高さ3段 | `--e-1/2/3` | 影の物差し（第1波・既存） |

**各ページのコンセプト（kiko-page の明るいブログ面・yt-page のダーク動画面・ig の黒 等）は
スコープ付きクラスとして正当**。トークンは値を1つも動かしていないので、ページの顔は不変。

## 見張り＝`tools/check_ui_tokens.mjs`（ラチェット）

直書きの数は一方向にしか動けない。天井（実測167）を超えたら赤。減ったら天井を下げて更新。
トークンの**二重定義**も検査する（--r-4事故の再発防止）。

## 規律（このファイルに違反する変更を入れないこと）
- 並行トークン系の新設禁止。定義は第1波ブロックだけ。
- 「完全一致の置換」と「値を動かす統一」を同じコミットに混ぜない。
- 新規CSSの角丸は var(--r-*) を使う（直書きはラチェットで落ちる）。
