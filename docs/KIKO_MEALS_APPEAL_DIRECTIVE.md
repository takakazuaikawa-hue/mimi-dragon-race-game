# Part A 紀行 — 「自分のプレイだけの記事が毎日書かれる」

## A0 リサーチ（実在の成功例から抜いた原理）
**『旅かえる』**（中国で大ヒットした放置ゲーの分析より）：
1. 写真が**プレイヤーごとに少しずつ違う**＝SNSに出したくなる・自分だけ感
2. **不確定性**（何を持ち帰るか分からない）が起動の動機になる
3. 持ち物の**組み合わせ→レア写真**＝収集のやり込みが自然発生

**人気旅行ブログの型**（トラベルライター向け解説より）：
- 命は**現地の臨場感とオリジナリティ**。読まれない理由の筆頭は「没個性」
- 読まれる中身＝搭乗記・宿泊記・レビュー・**失敗談**。冒頭で「読む価値」を示す

**診断**：いまの紀行はヘッダー（読者/売上）とタイムラインだけで、**「読める記事」が無い**。
タイトルを冠する画面なのに、プレイの実感と結ばれていない＝旅かえるの逆（何も届かない）。

## A1 設計の芯
**ミミの紀行＝プレイヤーの実プレイから自動で書かれる記事。**
一日の出来事（走ったレース・食べた品・撮った写真・歩いた場所）を材料に、
1本の「読める記事」が生成されて紀行に載る。

- **記事の型**（旅行ブログの型を移植）：見出し／リード（読む価値）／本文2〜3段落
  ／実データの差し込み（レース名・着順・オッズ・食べた品・撮った写真そのもの）／結び
- **切り口の不確定性**（旅かえる原理②）：同じ一日でも「敗戦記」「食レポ回」「絶景回」
  「竜自慢回」など**切り口テンプレを抽選**＝開くたび違う顔。素材が同じでも記事が違う
- **自分だけ感**（原理①）：差し込まれるのは必ず**そのプレイヤーの実データ**
  （撮った写真・実オッズ・実際の負け方）。失敗談テンプレ＝負けた日ほど記事が面白い
- **レア記事**（原理③）：条件の組み合わせで生まれる（大穴的中の日＝「バズ記事」・
  完敗の日＝「炎上せず励まされる回」等）。バズ記事は殿堂入り＝収集
- **読まれてる実感**：記事末尾に読者コメント2〜3件（既存SNSコメント資産の流用）
  ＋理由つき前回比「👀 読者 +55人（勝利のニュース +40／完走 +15）」（M4と統合）

## A2 実装の骨子（データ駆動）
- `js/kiko_articles.js`（新設）：切り口テンプレ台帳 `{ id, 条件, 見出しfn, 段落fn[] }`
  ＝素材（その日の state 差分）を受けて文章を組む。文体はミミ（既存の声表準拠）
- 生成タイミング＝ホーム到着時に「きのうの記事」1本（負荷なし・保存は素材のみ）
- 紀行画面の最上部に「最新記事」カード（全文が読める）。過去記事は5本まで保持＋殿堂
- 写真は既存の撮影データ（photoStars）を流用。無い日は写真なしレイアウト

## A3 決裁ポイント（Part A）
1. 記事の粒度：**1日1本**（推奨・ログイン印税と同じリズム）か、出来事ごとか
2. 過去記事の保持数：5本＋殿堂（推奨）か、全部残すか
3. 切り口テンプレの初期本数：8本から始めて育てる（推奨）

# Part B 食べ歩き — 「ひと口ゲーム」（10秒の読み合い）

## B0 リサーチ
- **龍が如く維新の料理**：切る/焼く/注ぐを**タイミング操作**＝出来で味が変わる
- **龍が如く7**：食事は仲間の絆・バフと結線（＝食事に「意味」を持たせる先例）
- **自前の成功型＝撮影ミニゲーム**：構図の選択→シャッターのタイミング、の2拍子で
  ☆1〜3。**選択＋タイミングの2拍子が本作の手に馴染む型**として実証済み
- **現状**：1〜2段（レース場飯・自宅ごはん）は**タップで文章が出るだけ**＝単調の正体。
  3〜4段（主役あて・隠し味あて）は既にクイズ＝ゲームになっている

## B1 設計の芯：実食を撮影ミニゲームと同じ2拍子に
**「どこから食べる？」（選択）→「いちばんうまい瞬間」（タイミング）→ 講評（☆1〜3）**

1. **ひと口目の選択**（3択・品ごとに正解が違う＝薄い読み合い）
   例：どて煮→「白い部分から／こんにゃくから／汁をひとくち」。
   ヒントは品の説明文に薄く仕込む（読む人が得をする＝テキスト資産が活きる）
2. **すすりタイミング**（横に動くゲージを頃合いで止める＝アツアツすぎず冷めすぎず。
   撮影のシャッターと同じ操作感・0.5秒）
3. **講評**：☆3＝既存の全力react（現テキストは☆3用として全部活きる）／
   ☆1〜2＝**新規の失敗オチ**（猫舌でアチチ・むせる・順番違いで師匠に叱られる等、
   失敗もコミカルで美味しい）。☆はベスト記録として保存（photoStarsと同型）
4. 3〜4段のクイズは現行のまま（すでにゲーム）。1〜2段に薄い読み合いが前倒しされる形

## B2 実装の骨子
- `showMealDetail` の eat モードに2拍子を挿入（guess モードは不変）
- ☆データ＝`state.player.meals[id].stars`（表示専用・コレクション採点は現行規則のまま）
- 1品の所要＝10秒以内。スキップ可（コレクション読み返し時は従来どおり即読める）
- 失敗オチのテキスト＝品ごとに1本（48品×1本・ミミの声表準拠）

## B3 決裁ポイント（Part B）
1. ☆の扱い：**表示・記録のみ**（推奨）か、総集編の採点に加えるか
2. 失敗オチは48品全部に書くか、まず1段目（レース場飯5品）で試作して体感確認か（推奨）
3. 紀行との結線：☆3の品はその日の記事の食レポ素材になる（Part Aと接続・推奨）
