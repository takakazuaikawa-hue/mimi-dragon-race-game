## §0 絶対規律（このセッションで実際に事故った作法。全条必須）

1. **レースの着順・オッズ・配当・コインに触れない**。しのびあしは表示＋収集のみ。旅費の精算箇所も従来のまま。
2. **機械検証してから完了と言う**。勝ち筋は「実装の関数そのものを駆動するBFSソルバ」で全組検証
   （手写しのシミュレータは実装とズレて誤検証になった実績あり）。解は**実機のUIクリック再生**で完走確認。
3. **自分で1周プレイしてから完了と言う**。座標検証は「遊べる」の証明にならない（[[playtest-before-done]]）。
4. **新しい記号は「①その場ラベル ②？一覧 ③凡例」の3点セット同時**。単独の記号は出さない。
   1回きりの初出ヒントに説明を頼らない（テスト実行が初回フラグを消費してユーザーに一度も出ない事故が起きた）。
5. **意味の違う表示に同じ色相を使わない**（黄視界×黄縞×黄緑背景で見分け不能事故）。
6. **竜スプライトは右向きが標準**。左を向くときだけ `flip`。3×3シートの background-position は 0/50/100%。
7. ラベル・バッジ類は**盤の overflow 内に置かない**（専用の固定行へ。端で切れる）。
8. デプロイ＝git plumbing で `main` と `flying-pixel-dragons` の**両方**へ。`?v=` バンプは **perl**（PowerShell禁止）。
   コミット後 `git log origin/main -1` で実在確認。
9. スクショはペイン非表示だと失敗する。1回目が真っ黒/古い場合は**もう一度撮る**（1フレーム遅れの既知現象）。
10. テストで進行フラグ（`_stalkCoach` 等）や図鑑（`scouted`）を汚したら**必ず元へ戻す**。

## §1 現状の構造（読む場所）

- `js/scout_stalk.js`＝本体。入口は `ui_scout.js scoutEnterLocation()` → `stalkAvailable(locId)`（今は grass のみ true）。
  流れ：`stalkDepart`（旅費・先読み）→ `_stalkRoll`（レア度抽選）→ `_stalkReveal`（段階リーチ）→ `_stalkStart`（盤面）
  → `stalkAct`（1ターン）→ `_stalkWin` / `_stalkLose`。
- 状態は `_stalk`：`{locId,d,tier,map,temper,mimi{c,r},drg{c,r,dir},alarm,turn,moveStreak,sleeping,sweeping,over}`。
  `dir` は 1=左/3=右のみ。`STALK_TURNS=24`。ソルバ実績：全24通り（気性4×map3×向き2）清潔勝ち7〜12手。
- 成立＝`_stalkWin` → 当たり演出（`.stalk-winfx`）→ `_scoutWin()`（`ui_scout.js`・龍舎登録/断章/八竜集結フック）。
- 図鑑登録は `poroColEntry(d.id)`（`state.player.collection`）。`e.scouted/e.seen`。

## §2 タスクA：成立ポップの簡素化（ユーザー決裁）

現状の `_scoutWin` のポップは「ミミの気持ち・重複説明・当然の注意書き」でテキスト過多。**絵が主役**に置き換える：

- 残すもの＝ **タイトル1行**「🤝 {name}と ともだちに！」／**大きなスプライト**（`.stalk-rv-card` と同じ
  レア枠リング・`_scSpriteInto` 流用・高さ140px級）／小さな1行「✨{銀/金/虹}クラス・気性 {…}」／
  **詳細への導線**＝ボタン「📖 図鑑で見る」（`renderPoroCollection` 系の既存図鑑へ。竜の個別ページが開けるなら directに）＋「わかった！」。
- 消すもの＝ミミの台詞（`_SCOUT_WIN_VOICE`）・「出会いの記録が増えた」行・「※表示専用…」注意書き・断章IIIの全文。
  断章IIIは**無言で解禁**し、小さな1行「📜 断章IIIが図鑑に増えた」だけ添える（＝詳細を見る動機づけ）。
- ⚠️ 置き換えても **`_maybeEightAssembly(isNew)` の呼び出しを必ず残す**（八竜集結VNの入口。閉じコールバックにある）。
- ⚠️ ポップの文言・行数はここに書いた以上に増やさない。「気を利かせた追記」が今回の粗の原因。

## §3 タスクB：♡後の「話しかけ」フェーズ（本命・ポケモンのゲット風）

♡に立ったら即成立をやめ、**話しかけ**へ入る：

### 画面
- 盤面を隠し、同じ枠内で：上部に**竜のスプライト大**（レア枠・向きはこちら向きでflip任意）／
  下に**話題ボタン3つ**（大きいアイコン主体）。テキストは話題名2〜4文字のみ。
- 話題プール6種（アイコン＋名）：☁️そら／🍖ごはん／🗺️たび／🌙ひみつ／🏁レース／🎵うた。

### 竜ごとに固定（消去法が成立する核・ユーザー決裁）
決定的ハッシュで**全竜ぶん自動生成**（手作業の台帳は作らない＝52頭スケール対応）：
```js
function stalkTalkSet(id) {
  let h = 0; for (const ch of id) h = (h * 31 + ch.charCodeAt(0)) >>> 0;
  const i0 = h % 6;
  const i1 = (i0 + 1 + ((h >> 4) % 3)) % 6;          // i0と必ず異なる
  const i2 = (i1 + 1 + ((h >> 8) % 2)) % 6;          // i0/i1と必ず異なる（届く範囲がずれるため）
  return { picks: [i0, i1, i2], answer: (h >> 2) % 3 };   // answer=正解の位置
}
```
※ i2 の重複回避は上式で保証されるが、**実装後に52頭全部で `new Set(picks).size===3` をループ検証**すること。

### 判定と再挑戦（ユーザー決裁どおり）
- 正解 → **成功**。既存の当たり演出（`.stalk-winfx`）→ タスクAの新ポップ。
- 不正解 → 竜が首を振る（！なし・警戒に**入れない**）。その話題は**永久にグレーアウト**：
  `poroColEntry(id).talkMiss = [外した picks の添字…]` に保存（セッションを跨いで消去法が効く）。
- 1回の話しかけ＝**👣4消費**（`s.turn += 4`）。残り👣が1以上あれば連続で再挑戦できる。
  残り👣が尽きたら `_stalkLose()`（飛び去り→もういちど探す）。
- **難度保証**：清潔勝ち最短7〜12手＋話しかけ最悪3回（4×3=12）＝19〜24 ≦ 24。
  実装後、ソルバを「♡到達＋(3−既知の外れ数)×4手」込みで回し、**全24通りで初回遠征から成立可能**を機械確認。
  1組でも不能なら `STALK_TURNS` を 26 に上げる（それ以外の数字は触らない）。

### 射幸の「間」（ユーザー決裁＝ドキドキする間→揺れ→成功）
話題を選んだら：ボタンを消す → 竜が**3回ゆれる**（600ms間隔・各回 Sfx "click"・リング微発光）→
**900msの静寂**（何も動かない＝タメ）→ 結果。成功はレア色の閃光＋`.stalk-winfx`、失敗は首振り＋「……ちがうみたい」。
アニメはCSSのみ・reduced-motion では揺れを省略して間だけ残す。

### 教える層（§0-4の3点セット）
- 初回だけ大バナー「🗣️ はなしかけよう（はずれても👣が残ればもう一度）」。
- ？一覧に「🗣️話しかけ／グレー＝この竜にはハズレだった話題」を追記。凡例は変更不要（盤面外のため）。

## §4 タスクC：全ロケ展開

- `stalkAvailable()` を常に true（全6ロケ）。旧フロー（`_scoutRenderProbe`/`scout_game.js` の読み合い・ダンス）は
  **呼ばれなくなるだけ**で削除しない（1コミットで戻せる状態を保つ）。手土産UIも使わない。
- 盤面マップは当面3種共用でよいが、**背景だけロケの `SCOUT_LOC_BG` を使う**（現実装が既に対応）。
- 旅費・解放条件・竜プールは既存のまま（`scoutLocation`/`unscoutedAtLocation` を変えない）。
- ソルバ検証は「マップ3×気性4×向き2」で足りる（ロケは背景が違うだけ）。ただし**各ロケ1回ずつ実機で1周**
  （プールの竜で reveal→盤→話しかけ→成立/失敗の通し）。⚠️ 検証で `scouted` を汚したら戻す。
