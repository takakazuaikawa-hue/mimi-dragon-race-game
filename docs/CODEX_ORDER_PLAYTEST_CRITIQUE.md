# CODEX_ORDER — 通しプレイ試験と「面白いか／製品の見た目か」の辛口批評（依頼先：Codex・2026-11-12）

> **納品＝報告書1本だけ。コード・画像・既存ドキュメントは変更しない。**
> 報告書は `docs/PLAYTEST_REPORT_<YYYYMMDD>.md` として新規作成する（既存ファイルは触らない）。
> 直すのはこちら（Claude 側）でやる。Codex は「遊んで、測って、辛口に書く」だけ。

## なぜこの依頼が要るのか

ユーザーの方針（2026-11-12）：

- **まず「面白い・よくできている・製品版の見た目」になっていること。** 細かな食い違いの検査はそのあと。
- 第1話でプレイヤーに脱落されるのがいちばん怖い。
- レースは、確率をいじらずに、見た目と演出で「何度でも挑戦したくなる」ものにしたい。
- 狙いは「ド貧困のミミが失敗と笑いを繰り返しながら、だんだん上がっていく、引き込まれてやめられないゲーム」。

Claude 側は直す作業に集中したいので、**通しで遊んで問題を洗い出す役**を Codex に頼みたい。

## 遊び方（環境）

- ブランチ `claude/compassionate-mendel-4e6ubv`（ドラフト PR #54）。`origin/main` ではない。
- 起動：`powershell -File serve.ps1` → http://localhost:8766/ （ビルド無し・静的ファイル）。
- **音は消して遊ぶこと**（ユーザーの他の作業に響くため）。ゲーム内の 🔊 から、またはコンソールで
  `Sfx.setMuted(true); Bgm.setMuted(true)`。
- 新規セーブから始める（コンソールで `localStorage.removeItem("mimi_dragon_race_v0_1")` → 再読み込み）。
- 画面は**スマホ縦（375×812）を主**に、360×640 と PC 幅でも1回ずつ見る。
- デバッグ用の「💰 +1万」などの下駄は**使わない**（実プレイの速度を測りたいので）。
  ただし第4話（総資産100万）以降は時間がかかるので、そこから先だけ使ってよい。使ったら報告書に明記する。
- レースは最初の5戦は**等速で最後まで見る**。それ以降はスキップしてよい（スキップしたくなった時点も記録する）。

## やってほしいこと

### A. 通しプレイ（新規セーブ → 行けるところまで）

次の節目ごとに、**所要レース数・所持金・そのとき何が起きたか**を表にする。

| 節目 | 見ること |
|---|---|
| 最初の1戦 | 何をすればいいか迷わず分かるか。竜を選ぶ画面は楽しいか。レースは見ていて盛り上がるか |
| 最初の服（ブニクロ普段着 2,000）を買うまで | 何戦かかるか。途中で「もういいや」となる場所はどこか |
| 第2話〜第3話 | 話が出るタイミングは気持ちいいか。唐突／遅すぎないか |
| 相棒（ポロ）と出会う | 2勝めのあとに出るか。出会いは印象に残るか |
| 紀行（連載・日々の記事） | 書きたくなるか。読んで面白いか。書くと何が得かが伝わるか |
| おでかけ・食事・着替え・くらしツリー | それぞれ「行く理由」があるか。入口で迷わないか |
| すっからかん（無心） | 笑えるか。ただの救済になっていないか |
| 第4話以降 | 作業感が出るのはどこからか |

賭け方は2通りやる：**①単勝1番人気に賭金そのまま**／**②気になった竜に賭金「最大」**。

### B. 辛口の批評（遠慮なく。褒めなくていい）

画面ごとに、**製品として売れる水準に届いていない点**を重い順に書く。
「なんとなく微妙」は不可。**どの画面の・どこが・なぜ弱いか・どう直すと良くなるか**まで書く。

見る観点：

1. **第一印象**：最初の30秒で「遊びたい」と思えるか。タイトル→ホーム→最初のレースの流れ。
2. **レース画面**：走る絵の迫力、自分の竜の見つけやすさ、実況の面白さ、ゴールの盛り上がり、1戦の長さ（等速で約65秒）。
3. **竜を選ぶ画面**：竜に愛着がわくか。数字の表に見えていないか。
4. **結果画面**：勝ったときの気持ちよさ、負けたときの笑い・次への動機。
5. **レイアウト**：文字の大きさ・余白・はみ出し・押しにくいボタン・情報の詰めこみすぎ。
6. **演出**：動き・間・音（音は消して遊ぶので、見た目の演出だけでよい）。
7. **テンポ**：会話や通知が多すぎて止まる場所、逆に何も起きず退屈な区間。
8. **物語**：ミミに感情移入できるか。貧乏と失敗が笑いになっているか。

### C. 見つけた不具合

再現手順つきで。**進行が止まるもの・主役の機能が出ないもの**を先に、表示の乱れはあと。

## すでに分かっていること（重複して書かなくてよい）

`docs/STATUS_LEDGER.md` の先頭の節（2026-11-12）に、こちらで見つけた問題と直した内容がある。先に読むこと。要点：

- 最初の注目レースが「1番人気 0勝」のレースに当たることがあった → はじめの3戦は第1レースに固定した。
- 1番人気の勝率（16〜27%）は、オッズが示す値（48〜58%）の半分以下。**これは仕様の可能性がある**ので、
  「バグ」としてではなく「初心者がどう感じるか」として書いてほしい。
- 賭金100のままだと、15戦しても最初の服に届かない。全額を失って無心すると 5,640 もらえる。
- 借金（自力分3万）が、0勝のまま5戦めで完済になる。
- 「後回し」に挙げてある細かな食い違い（会話の場所・食べもの、目標の達成タイミングなど）。

## 触ってはいけないもの

- レースの数値（着順・オッズ・配当。`race_engine.js`／`odds_engine.js`／`betting_engine.js`）。**提案もしない**
  （「確率を変えるべき」という指摘は不要。見た目・演出・導線・文言・テンポで解決する案だけ）。
- `main` への push、コード・画像・既存ドキュメントの変更。
