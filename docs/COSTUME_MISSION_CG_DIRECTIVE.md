# 👗 衣装ミッション＋ご褒美CG 指示書（**第1弾8着 実装済み**・発案 2026-08-03／量産 2026-09-19）

> ユーザーの言葉（原文の趣旨）：「衣装ごとのミッションイベント（〇〇へ行く、〇〇を食べる、
> 〇〇レースで勝つ）でご褒美CGもいいですね」。実装は**あとで Opus 5 に任せる**。
> この文書は発案の記録＋守るべき前提の束ね。設計の再議論はここから始めてよい。

## 芯
衣装（モールの戦利品 `outfitsWon` / 購入 `outfitsBought`）ごとに小さなミッション列を付け、
達成すると**その衣装を着たミミのご褒美CG（一枚絵）**が開く。
- ミッションの型＝「〇〇へ行く」（島歩き/観光スポット）・「〇〇を食べる」（食べ歩き）・
  「〇〇レースで勝つ」（実績参照）＝**すべて既存の状態を読むだけ**で判定できる形にする
- CGはコレクション（図鑑/フォト日記の並び）に収まり、いつでも見返せる

## 守ること（既存の憲法）
- **レースの着順・オッズ・配当・FinalPower は不可侵**＝ミッションは表示/収集メタ。
  「〇〇レースで勝つ」も既存の勝敗を読むだけ（勝率へ干渉する誘導は書かない）
- 拡張契約（GAME_EXPERIENCE_DESIGN §4）＝**駅/発見/結線の3点セット**を必ず書く：
  入口（衣装入手時に1口だけ告げる？黙って置く？）・出口（CG獲得後の次の一手）・
  発見マトリクスのどのマスか（告知7:余白3——**全部は告知しない**）
- キャラの門番（advisorMet/castNameSafe）＝ミッション文に未登場キャラの名を書かない
- 新フラグは増やさない方針を踏襲（くらしツリー授与22件と同じ相乗り式が理想）
- 計器禁止＝「達成率◯%」バーを置かない。ミッションは読み物とチェックの形で

## ご褒美CGの生成（Higgsfield）
- 参照画像＝既存のミミ立ち絵（服はその衣装のドット/メタ説明から言語化）で一貫性を取る
- 作法は [[higgsfield-anime-keyvisual-lessons]] 厳守（photorealistic禁止・寄りは鎖骨で切る・
  文字は入れない等）。単価実測＝Nano Banana Pro 2cr/枚・撮り直し込みで1枚あたり4〜8cr見込み
- 衣装数ぶん量産する前に、**1枚だけ作ってユーザー決裁**（画風・構図の基準を先に固める）

## カットインの様式（2026-08-03 決裁済み・実装済み＝Opusは再実装しないこと）
- 取得系のカットインは**元の showLifeCutin**（閃光＋集中線＋斜め帯・`#lt-cutin`）に一本化済み。
  自作の別様式を増やさない（「元のチープなやつが好き」＝ユーザーの明示の好み）
- 滞留は 2.4秒＋タップ即閉じ（「クリックする前に消えて読めない」の修正済み）。
  複数連続時は前が閉じてから次（重ねない）。CG開示の演出もこの様式の延長で設計する

## 実装状況（2026-09-19・第1弾）

**8着ぶんのミッション＋ご褒美CGを実装・デプロイ済み。** 台帳＝`js/costume_missions.js`。

|---|---|---|
| 素寒貧ミミ | はじまりの記録 | 霧港へ行く／塩むすび／はじめての1着 |
| モールでお買い物 | おでかけの記録 | モール制覇／崑崙モール／品20 |
| お手頃水着 | 夏の記録 | セナ浜／バンガラ溶岩海岸／かき氷 |

| 予想新聞ドレス | 予想家の記録 | 中央レース場／勝負めし焼き鳥／通算10勝 |
| 台北チャイナドレス | 夜市の記録 | 霧待ち市場／夜市の古布屋／たこ焼き |
| もこもこルームウェア | おうちの記録 | のり茶漬け／卵かけごはん／カップ麺 |

型は「行く」「食べる」「勝つ／集める」の3手。判定は**すべて既存stateの読み取りだけ**
（`spotsSeen` ／ `MEALS` の `eaten` ／ `scoutedRoster()` ／ `player.wins`）で、新フラグは増やしていない。
持っていない衣装のミッションは**表示されない**（fail-closed）。

### 生成の作法（実測）
モデルは **`seedream_v5_pro`**（3cr/枚）。**その衣装の立ち絵を参照画像に渡す**と、顔・髪・兎耳・
衣装の細部まで揃う。旧 `seedream_v4_5` 製だった leonmall も同じ工程で撮り直し、画風を8枚で統一した。
規格＝**1000x1333 / WebP q80**（既存 cg_leonmall と同じ）。8枚で計 1.3MB（1枚ずつ開くビューア用）。

### ★参照先の監査（必須）
`tools/audit_costume_missions.js` — ミッションが読む **spot / meal / outfit / CG画像** が実在するかを
機械的に照合する。存在しない id を書くと「**永久に未達成のミッション**」になり、画面上は静かに
壊れて誰も気づけない。ステップを足したら必ず走らせること。
検出力も検証済み（id を故意に壊すと2件を検出して exit 1、戻すと exit 0）。

### 次弾の候補
残り34着。物語の節目と結びつく順に足す（例：バンギャ＝ライブ、遊園地＝セイリュランド、
就活スーツ＝行政街、メルメス・バニー＝資産の頂）。**1着につき既存stateで判定できる3手**が
書けるかどうかが採否の基準。書けない衣装は無理に足さない。
