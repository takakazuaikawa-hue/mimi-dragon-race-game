# ゲーム体験設計（最上位の正本）— GAME_EXPERIENCE_DESIGN

**この文書がゲーム全体の傘。** 配下：PROGRESSION_DESIGN.md（章＝縦軸の解放）／
KURASHI_STORY_WEAVE.md（暮らし還流）／HOME_COMMERCIAL_REDESIGN.md（ホーム）。
鉄則：全機能は表示専用/ゲートのみ（[[race-math-immutable]]）。

## 0. 体験の柱（3本・全機能はこのどれかに奉仕する）
1. **予想の手応え** — 竜を見て・根拠を持って賭け・結果に痺れる（コア）
2. **島で生きている実感** — 食べ・歩き・育て・買う。勝敗の外に人生がある
3. **見られている喜び** — 配信・ファン・日報。自分の行動に世界が反応する

## 1. 島の一日ループ（横軸・1セッション＝ミミの一日）
プレイヤーが自然に巡る「駅」。**各駅は次の駅を1つ指す**（§3の結線ルール）。

```
 🌅 ホーム（配信開始）        「今日は何をする？」＝🎯目標・📸今日の一枚・ミッション
   ↓
 🐲 レース（予想→観戦→結果）  コア。1日1〜3走
   ↓ 勝ち／負け
 🍽 ごはん（勝ち飯／負け飯）    結果を感情で締める。コレクション進行
   ↓
 🏝 島時間（選べる寄り道）      観光スタンプ・買い物・龍舎/スカウト・くらしツリー・習い事
   ↓
 📱 夜のSNS（世界の反応）       タイムライン・ファンレター・日報の新記事
   ↓
 🌙 ホームに戻る（配信締め）     目標更新・還流toast・「また明日」
```
- ループは強制しない＝**提案**（次の一手チップ）。スキップ自由・順不同OK。
- 1周15〜30分想定。章が進むと「駅」に新しい行動が増える（§2）。

## 2. 発見マトリクス（縦軸×発見の3種）
章ごとに必ず3種の発見を用意する。**空欄＝将来の追加スロット**（ここに足す）。

| 章 | 🚪新しい場所 | ✋新しい行動 | 💬新しい反応（世界が変わる） |
|---|---|---|---|
| 序章 | 図鑑（初的中） | 屋台で食べる | 村人の声・目標チップ |
| 2話 | モール／観光（初勝利） | 分析予想・着替え | ミズの市況記事・相談 |
| 3話 | くらしツリー・生活資産・龍舎 | 育てる・スカウト交渉 | スミカの宿題・引っ越し記事 |
| 4話 | 配信ホーム・SNS | コメント/🎁/❤️・習い事の師範 | フォロワー増・VIP入場・ファンレター |
| 終章 | 島の経済（絶滅メーター）・上級グルメ | 神眼コンサルト・最終決戦 | 避難基金記事・島総出の応援 |
| クリア後 | コレクション得点・グルメレース/タワー | 全収集の周回 | 復興記事・個人化スタッフロール |
| （空欄例） | 新エリア/新施設 | 新ミニゲーム | 新しい日報面/新キャラの手紙 |

**発見の作法**：解放は progression 台帳（cut-in/toast・1到着1件）。ただし**全部は告知しない**
——「？？？」枠・観光の未踏スポット・食事の？？？カード・小イベント等は**自分で見つける余白**として残す。
比率目安＝告知する発見7：黙って置いておく発見3。

## 3. 導線の結線ルール（次の一手エンジン）
**すべての「区切りの画面」は、文脈に合う次の一手を1〜2個だけ提案する。**
実装＝`js/next_suggest.js` の **NEXT_SUGGEST 台帳**（データ駆動・表示専用）：
`{ at: 画面id, cond(state,ctx), icon, label, go, weight }` — at ごとに cond を満たす中から weight 上位1〜2個。

初期結線（M1〜）：
| 区切り | 提案（文脈） |
|---|---|
| レース結果（勝ち） | 🍽「勝ち飯を食べにいく」／📱「みんなの反応を見る」(配信時) |
| レース結果（負け） | 🍽「負け飯で立て直す」／🌳「くらしツリーに1節」(P残あり時) |
| 食事のあと | 📸「今日の一枚を見にいく」(未達成時)／🐲「次のレースへ」 |
| 観光のあと | 🐲「次のレースへ」／📱「SNSに反応が来てる」(未読時) |
| SNSのあと | 🌙「ホームへ（配信締め）」 |
| 章を読んだ | その章の新解放へ（progression の cut-in が担当・重複させない） |
- 提案は**押しつけない**：小さなチップ1行・無視して従来ボタンも常に有効。
- **追加規約**：新機能を作ったら NEXT_SUGGEST に「入口1件・出口1件」を必ず登録する。

## 4. 拡張契約（あとから足すときの3点セット）
新機能・新コンテンツは以下3点を決めれば骨格に収まる（1つでも欠けたら設計不足）：
1. **駅**：一日ループ（§1）のどの駅に属するか（新駅は原則作らない）
2. **発見**：発見マトリクス（§2）のどのマスか（章×種類・告知するか黙って置くか）
3. **結線**：NEXT_SUGGEST の入口/出口（§3）＋還流するなら KURASHI_WATCH/小イベント/手紙（KURASHI_STORY_WEAVE）

## 5. 実装ウェーブ
- **M1 次の一手エンジン**：next_suggest.js＋レース結果の勝ち飯/負け飯（最重要の断線＝結果→島時間）
- **M2 各駅の出口**：食事/観光/SNSの出口チップ・ホームの「今日の一枚」ミラー
- **M3 発見の余白監査**：告知7:余白3になっているか棚卸し・？？？枠の追加
- 以後：新機能はすべて§4の3点セットで追記（この文書の表に1行足す）
