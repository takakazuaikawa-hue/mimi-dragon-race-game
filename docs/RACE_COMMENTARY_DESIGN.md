## 1. 【結論】プレイヤーに何を感じさせるのか

プレイヤーに感じさせるのは「レースの理解」ではなく、**自分がすでに張った予測が、まだ生きているか死んだかという一本の心拍**である。賭けを確定した瞬間に当事者性は完成しているので、実況が賭け竜を代弁する必要は一切ない。実況の仕事は、着順の行方を**読める短さ**で刻み続けることで心拍を上下させること。解説の仕事は、レース開始時に**自分の見立てを言い切って第二の賭けを場に置き**、決着でそれが当たったか自爆したかを晒すこと。この二層があるとき、プレイヤーは自分の馬券と解説者の予言という二本の線を同時に握り、着順が決まる0.5秒に二つの答え合わせが同時に来る。ゴールで感じさせるべきは「当たった／外れた」ではなく、**「どう決まったか」と「あと何が足りなかったか」**である。

| 場面 | プレイヤーの内心 | それを作る担当 |

## 4. 【実況のスタイル指針】

### 守る原則

1. **語順を固定する**：〈縦位置 → 内外 → 竜名〉。固有名詞は必ず文末。「コガネが3番手です」ではなく「三番手、内をすくって、コガネ。」——名前が最後に来ると、プレイヤーが盤面を目で探す0.3秒が生まれ、単行表示と噛み合う。
2. **文長でテンションを表す**。「！」の増量は音のない媒体での逃げ道。入場16字→序盤14字→中盤15字→終盤8字→決着12字。直線が短くなること自体が加速に見える。
3. **差は必ず量で言う**。着差目盛りを新造し5段階で統一：**鼻先／首差／半身／一体／大差**。「接戦」「混戦」は情報量ゼロとして禁句。
4. **差の変化は2値並置**。「リードは二体から三体。」（開く）「三体が一体に。」（詰まる）。単一の数値より運動として伝わる。
5. **動詞を脚質で分離**。差し＝来た/迫る/割って入る/差し切った。逃げ＝行った/粘る/しのぐ/残す/離す。読み手は動詞で追う側を判断している。
6. **呼称をローテーションする**。同一竜の1回目＝竜名、2回目＝異名、3回目＝色。既存の異名システムがそのまま実況語彙になる（ただし短縮形を別途データに持つ、後述）。
7. **「さあ」は1レース4回まで**。仕掛け・先頭交代・直線入口・最後の一完歩のみ。乱発すると合図が死ぬ。
8. **際どければ数値を捨てる**。「並んだ。」で止める。実況の最悪は誤情報で、判定は着順ボードの仕事。

### してはいけないこと（禁句リスト＝一元管理）

- 頑張れ／頑張っている／必死だ／熱い戦い／目が離せない／すごい迫力／大興奮
- 並んでいます／接戦です／混戦／いい勝負
- **ゴールイン！**（どの決着でも成立するので決め手にならない）
- あなたの／本命／期待の／〜さんの（賭け竜への**間接**言及も違反）
- 序盤の勝者示唆（「これは強い」「もう決まりでしょう」）＝サスペンスの自殺
- 4番手以下の入れ替わり（ただし**3着以内に絡む可能性のある後方竜は例外**——「6番手から差してくる竜」は上位争いの一部）
- 判定の先取り（「Xが優勢です」）——直後にボードが違う結果を出すと実況全体の信頼が一撃で崩れる

### 機械チェックの実装方針

**形態素解析は使わない**（kuromoji.js は数MBでPWAに載らない）。代わりに行データに`needsFact:["rank","gap","name"]`のような**事前タグ**を持たせ、
- 禁句：正規表現でビルド前チェック（`devcheck.js`実行時検査）
- コピペ検定：文面の再利用性ではなく**「その行が走行データを1つ以上参照しているか」**で判定する。`needsFact`が空の行は`flavor:true`か`finish:true`のタグがなければ落とす。これなら終盤の「外から、外から。」（needsFact:["move"]）は生き残り、「熱い戦いです」（needsFact空・flavorなし）だけが死ぬ。

**同一局面IDに6本の“訳文”をぶら下げるだけ**で描き分けが立つ。キャラ設定文を一切読ませずに伝わるのがこの分け方の価値で、しかも**物差しは摩耗しない**（ネタは2回目で死ぬが、新しい局面が増えるたび笑いが自動で1つ増える）。

### 摩耗させない5つの仕掛け

1. **予言＝笑いの生成器（主機構）**。作り手はオチを書かない。オチはレース結果が毎回無償で供給する。
2. **技タグの排他**。同一レース内で同じtechniqueを2回使わない。解説者ごとに使用可能技を限定。
3. **レース内とレース跨ぎで運用が正反対**。レース内の天丼は1本まで・3回目で必ず変化。レース跨ぎの決め台詞は**一字も変えず**、厳格な発動条件でのみ出す（スミカ＝大差決着限定、ウンメ＝鼻先決着限定）。20レース目に「来た！」が生まれる。
4. **固有解説はレア枠に隔離**。6人×5〜8本＝40本。条件：最下位からの逆転／同一竜3連勝／初勝利／宿敵への差し返し／大差圧勝／鼻先決着。一度出たら**30レース封印**、汎用行も直近10レース除外のスライディングウィンドウ。プールが枯れたら古い順に解放（クラッシュしない）。
5. **ミミの温度を相手で反転させる**。ミミの行に`relation:hot/cool`を持たせ、マクラ（熱い）の回はミミが冷静に刻み、スミカ（冷たい）の回はミミが熱くなる。同じミミが6通りの温度を持つのが「6レースが6種類の番組に見える」正体。

### 規律（審査指摘の修正込み）

- **全解説行は「情報1つ＋味付け1つ」の二層**。ただし**1レースに1本だけ純ボケ枠**（情報義務免除）を許す。全行に情報義務を課すと上品な小気味よさで平坦化する。
- **笑いの発火位置を規則化しない**。「谷にだけ鳴らす」を厳格運用すると20レースで「ここ笑うとこだ」と読まれる。谷を**優先**するが、余韻・中盤・（稀に）序盤に確率的に散らす。
- **毒舌には必ず愛をセットにする**。スミカは消耗を嘆いた後、必ずねぎらいで終える型を固定。
- **抽選は直近2人を除外するローテーション**。完全ランダムだと連続で出て「6人いる」価値が壊れ、間隔が空きすぎると跨ぎ天丼が育たない。
- **キャスト門番（`advisorMet`相当）をfail-closedで通す**。データに条件が揃っていても未登場の解説者は絶対に出さない。

## 6. 【エンジン構造】

### 6-1. まず「どこを直すか」を確定する

**実働経路は `js/race_broadcast.js` の `buildBroadcast()`**。`race_canvas.js:1740` は `if (!telopSchedule.length)` ——つまり `js/commentary_engine.js`（`PHASE_LINE_TARGET` / `PHASE_TEMPO`）は**フォールバック**であり、そこを直しても本番出力は1行も変わらない。設計案がここを取り違えると「実装したのに何も変わらない」が起きる。

もう一つの経路 `js/race_beats.js` には **`ZONE_IN`/`ZONE_OUT`（自分の賭けが的中圏内に入った／外れた）が最優先級で生きている**（`:57-58, :262-271`）。これはユーザー指示の直接違反であり、**最初に撤去する**。

### 6-2. 3段 → 5段へ

```
[1] 解析  bcAnalyze()拡張   … 既存 + hope(t) + 予言候補の抽出
[2] 作譜  scoreBeats()新設  … 感情の設計図（ビートと熱量）を先に引く
[3] 削り  budgetPack()新設  … 候補を全部出し、優先度で削る
[4] 執筆  write()改修       … 文長カーブ・語彙辞書・語義タグ
[5] 発火  schedule()改修    … 二段遅延・可変beat・沈黙予約
```

### 新規に必要な解析項目

**(a) hope(t) — 単一の派生スカラー（UIには出さない）**

既存 `bcAnalyze()` が持つ `A.samples / A.gaps / A.leadChanges` から計算する派生値。新データ源もシミュレーションも不要。

```
hope(t) = w1 * (1 - normalize(上位2頭の勝率差))     // 拮抗度
        + w2 * normalize(生存候補数)                  // 収束度
        + w3 * max_i(勝率上昇率_i)                    // ★第三の竜の突進
```

第3項が審査の指摘への対応：上位2頭だけで定義すると、**3番手以下から突っ込んでくる竜が構造的に曲線を動かさず、実況も演出も反応しない**。最大上昇率の竜を混ぜて初めて差し竜の予兆が拾える。

hope は**2つのことにだけ使う**：①行の採否スコア（`|Δhope|`が大きい瞬間に行を寄せる）②行の保持時間（傾きが急なほど短く速く）。

**★ 希望メーターとしてUIに出すことは禁止する。** 理由は3つ：(1) 結果を知った上で引かれた曲線なので、可視化はレースが答えを出す前に答えを見せる。(2) 「自分の線が生きているか」を伝えるには自分の線を識別表示する必要があり、それは実質的な賭け竜言及＝ユーザー指示の潜脱。(3) `TL_FINISH_DRAMA`（先頭3頭を意図的に団子にする演出）が噛んでいるため、素直に勝率化すると演出上の団子と本当の勝率がズレる。**hope は内部変数に留める。**

**(b) 予言候補（prophecy）**

```js
{ id, text, verify(timeline)->bool, pairId, targetIds }
```

**設計上の絶対規則が2つある：**

1. **候補は入場時点の公開情報のみから導出する**（人気・脚質・天候・コース・竜の履歴）。**verify の結果を見てから当たる予言／外れる予言を選ぶことは禁止**。的中率を1/2に「調律」すると、数十レースで「断定が強い日は当たる」というtellとしてプレイヤーに学習され、気づいた瞬間に第二の賭けが完全に死ぬ。**素直に当たり外れさせる。** 結果として的中率が偏るなら、候補テンプレの側（成立しやすい予言／しにくい予言の比率）を事前に調整する。
2. **予言の対象は「最終3着以内に絡む竜」または「先頭交代・着差そのもの」に限定する**。これがないと、解説予算のほぼ全部が7着の竜の話に消えて、レースが見えなくなる。

**候補ゼロ時のフォールバック台詞を最初に用意する**（入場の見立ては三幕構成上必須なので、欠けると開幕に穴が開く）。

**(c) 着差段階の判定関数**

`marginTier(gapMeters) -> "鼻先"|"首差"|"半身"|"一体"|"大差"` を**単一関数に集約**し、実況・ミニ隊列表示・着順ボードの三者が同じ関数を呼ぶ。実況が「半身」と言った直後にボードが「半身」と出る＝実況が嘘をついていない証明。ここが不一致だと信頼が一撃で崩れる。

**(d) 竜の語義タグ**

52頭に1語ずつ。フガク＝嶺／コガネ＝黄金／クロガネ＝黒鉄。決め台詞を「〈語義の情景〉、〈竜名〉。」の体言止めで生成する。**1竜1行の追加データで52種の固有の決着行が生まれる、最もコスパの高い施策**。

### 6-3. 作譜と削りの規律

- 行数は「入れる枠」ではなく**「削った残骸」**。候補を全部出す（1レース60〜80本）→ `(novelty × stakes × 未使用ボーナス × criteria数) / cost` の降順で秒予算に詰める → 入らない分は捨て、**捨てた候補を`devcheck`にログ出力**してチューニング可能にする。
- **novelty は瞬間`|Δhope|`ではなく期待将来`Δhope`を使う**。瞬間値だと「後方クロガネ、まだ動かない」という最も価値の高い伏線行が最低点になり、差し竜の予兆が消え、勝者が最後の3秒に無から出現する。伏線行には明示的ボーナスを与える。
- **沈黙を先に予約する**（中盤1.5秒×2、ゴール前0.8秒×1）。現行 `say()` は `at = Math.max(tau, lastT + gap)` で後ろへずらす設計なので、予約枠は**通過禁止領域**として扱う制約付きスケジューラに書き換える必要がある。
- **独走レースの分岐は必須**。hope が全域で低い場合、語りの主題を「2着争い」へ切り替える。ただし切替先の候補行・語彙・尺配分を**先に用意しておく**こと（用意せずに分岐だけ書くと、最も退屈なレースが最も退屈に実況される）。
- **決定性を守る**。`race_timeline_engine.js` は「同じレースは何度描いても同一」を保証するシード付きRNGを持つ。選抜アルゴリズムで `Math.random()` を踏むと再現性が壊れる。既存の `seed`（`race_broadcast.js:155,188,191`）に接続する。

### 6-4. 熱量レベル（審査指摘の修正込み）

`tone:1..5`。**「レース全体で単調非減少」は採らない。** 5に達したら下げられない規則は終盤10秒を常時フルスロットルにし、感覚を麻痺させる。盛り上がりは絶対値ではなく落差で生まれる（この案自身の「沈黙直後は2倍重い」と矛盾する）。

採用するのは**「局面内では単調非減少、局面境界でのみ1段リセット可」**。序盤は tone 2 以下に強制ロック。tone は文字サイズ・太さ・字送り・句読点密度で表す。

## 7. 【前提変更の提案】

### 変えるべきもの

| # | 変更 | 理由 |
|---|---|---|
| **1（最優先）** | **1行の文字数を半減する。** 実況 標準12〜16字／保持1.4秒、決め行のみ24〜30字／3.0秒。解説 18〜22字／1.8秒、オチ行のみ長く | 30字/1.0秒＝30字/秒は、映像字幕の実務基準（4字/秒）の7.5倍、黙読上限（10字/秒）の3倍。**物理的に読めていない**。行を増やすのではなく1行を短くする |
| 2 | **保持時間を固定から可変へ**。`chars ÷ 読速 + beat(0.4〜1.6秒)`。**ただし下限0.8秒**（0.4秒では1.6〜4字しか読めず、最も展開が動く終盤で最も読めなくなる） | 等間隔＝間がない。オチ前の溜めとオチ後の余韻がないと笑いは原理的に成立しない。総再生時間を変えずに実装できる |
| 3 | **入場 9.4→5.4秒、カウント 3.0→2.0秒**。`ENTRY_WALK 3.8→2.4`, `ENTRY_STAGGER 5.0→2.4`, `PRE_TOTAL 3.0→2.0` | 冒頭0〜2秒は最も離脱する区間。情報のない行進を置くのは最悪手。※`race_canvas.js:1354/1858/3393`が`ENTRY_DUR`依存なので**見た目のタイミング再調整が3箇所発生する**。表示専用なので結果・オッズ・配当には一切影響しない |
| 4 | **余韻5秒を新設**（削った分を全額移す） | ピーク・エンド則。「ゴールインでは決め手にならない」というユーザーの直感は「エンドが弱い」という正確な診断 |
| 5 | **上位3頭の隊列を常時表示**（既存の「残り◯m」表示と**1行に統合**する。独立バーは初手から捨てる） | 縦持ちで HUD＋盤面＋52px×2の吹き出し＋着順ボードが既に詰まっている。**盤面を削ってまでバーを足すのは本末転倒**。統合が本命 |
| 6 | **実況と解説を同時に切り替えない**。片方が更新される瞬間、もう片方は静止＋暗転 | 52px×2段の同時更新は瞬間認知負荷が倍。話している側だけ点灯するのが「二人が会話している」という表示そのものになる |
| 7 | **着差目盛り5段階を新造し、実況・隊列表示・着順ボードで共用** | 実況の発言が検証可能になる。UI追加コストほぼゼロで「レースが見える」度が上がる |

### 変えない方がよいもの

| # | 据え置き | 理由 |
|---|---|---|
| 1 | **走行42〜56秒** | 実競馬の芝1200mが約68秒。46秒は既に十分長い。伸ばすと周回コストだけ増え、ショート動画の維持率的にも離脱を招く |
| 2 | **総行数（実況20〜24／解説8〜13）** | 増やしても読めない行が増えるだけ。問題は行数ではなく1行の長さと配分 |
| 3 | **既存のスキップ実装**（`race_canvas.js:4335`）と 2×/3× 速度ボタン | 完全スキップは現代の標準装備で、無いこと自体が減点。**「スキップ時も5秒強制再生」はやらない**——押した人は結果が見たいのであって、そこに強制を足すのは改悪。代わりに**決着2行をテキストとして結果画面上部に載せる**（読み飛ばせる形で価値だけ渡す） |
| 4 | **レース結果・オッズ・配当** | 憲法。すべて表示層のみ |
| 5 | **余韻の尺（周回時に削らない）** | 余韻は予言回収オチが乗る＝周回で唯一中身が変化しうる場所。周回で削るなら**入場の情景描写と序盤**であって、最も飽きにくい区間を先に削ってはいけない |

### 速度倍率（2×/3×）への対応 ※見落としやすい罠

`race_canvas.js:4084` は `adv = dt * S.speed / durationSecHint`。**このまま実装すると、可変beat・0.8秒の沈黙・0.6秒の溜めがすべて 1/3 に潰れ、「12〜16字を1.4秒で読ませる」という可読性の根拠も3×では0.47秒になって崩壊する。**

対応：**beat と保持時間は実秒で固定し、倍速時は行を間引く**（優先度下位から捨てる）。倍速は「速く読む」ではなく「要点だけ見る」モードだと定義する。

## 9. 【実装ロードマップ】

### Phase 0：違反の除去（半日）
- `ZONE_IN`/`ZONE_OUT` を撤去、`buildBroadcast()` から `ctx.bet` を除去、入場の `why:"mine"` を削除
- 禁句リストを `devcheck.js` の実行時検査に追加
- 賭け竜はレーン端の細い下線マーカー（視覚のみ）に降格

**良くなること**：ユーザー指示への完全準拠。奪われた行数が着順の行方に戻る。

### Phase 1：読める実況（1〜2日）★単独で最大の効果
- `marginTier()` を作り、実況・着順ボードで共用
- 実況を12〜16字に短縮（局面ごとに maxLen、既存行に short 段を追加。旧形式も読めるアダプタ層を先に入れて `poolOf` の無言事故を防ぐ）
- 保持時間を `chars ÷ 読速 + beat`（下限0.8秒）に。倍速時は実秒固定＋行間引き
- 実況と解説の同時更新を禁止（点灯／暗転）

**良くなること**：文字が**実際に読める**ようになる。テンションが文長で表現され、終盤が加速して見える。「半身」がボードと一致して実況が信用される。ここまでで体感の大半が変わる。

### Phase 2：hope による削り（2〜3日）
- `bcAnalyze()` に hope(t) を追加（第三の竜の上昇率を含む）
- `budgetPack()` で「候補を全部出す→優先度で削る」に置換。捨てた候補を `devcheck` にログ
- 沈黙を予約枠として先に確保（中盤1.5秒×2、ゴール前0.8秒）
- 独走レース検出 →「2着争い」への主題切替（切替先の候補行も同時に用意）
- 序盤に上位3頭スロットを1回通す（初期地図）＋発走の出遅れ行を必須化
- `devcheck` の自動レースで「hope の山谷と盤面イベントの一致率」を機械計測

**良くなること**：盛り上がりの山に行が寄り、平坦な区間から行が消える。同じ行数で体感密度が上がる。差し竜の予兆が拾われ、勝者が無から出現しなくなる。

### Phase 3：予言と余韻（3〜4日）
- prophecy / verify / pairId を `say()` の上に追加（tag欄にpairId、script[]に当たり系統・外れ系統の2本）
- 候補ゼロ時のフォールバック台詞を**先に**用意
- 入場5.4秒・カウント2.0秒に圧縮（`race_canvas.js:1354/1858/3393` の見え方を実機で再調整）
- 余韻5秒を新設。決着2行（決め手＋着差＋反実仮想）
- 竜52頭の語義タグを整備し、決め台詞をデータ駆動生成

**良くなること**：「第二の賭け」が成立する。ゴールが「ゴールイン」から「どう決まったか」に変わる。毎レース違うオチが台詞を足さずに生まれる。

### Phase 4：常時表示と6人（3〜4日）
- 上位3頭の隊列を「残り◯m」に統合表示（**実機で高さ実測してから**、実況の隊列説明を削る。順序を逆にしない）
- 解説を criteria 付きレコードに移行（technique / beat / flavor / relation / rarity）
- 換算単位に紐づく終盤の固有相槌
- 直近2人除外ローテーション＋キャスト門番（fail-closed）
- ミミの relation 別台詞プール

**良くなること**：中盤の隊列説明の反復が消え、その行が笑いと情緒に回る。6人が設定文なしで描き分かる。

### Phase 5：長期耐久（継続）
- 固有解説40本＋used30レース封印＋スライディングウィンドウ（**state スキーマ変更を伴うので、移行と破損時フォールバックを設計してから着手**）
- レース跨ぎの決め台詞（発動条件を厳格固定）
- 3段階昇格の視覚・音演出

**良くなること**：20レース目に「来た！」が生まれる。ただし**長期の飽きは実況エンジンの責任ではない**——変化は章の進行・解説者の解放・宿敵の発生という外側のループから供給する分業を明文化しておくこと。エンジンに無限のコンテンツを背負わせない。

## 10. 検証の契約（「完了」と言う前に満たすこと）

1. `devcheck` の自動レース50本で、**禁句が0件**・**賭け竜への言及が0件**（構造レベルで `ctx.bet` が実況経路に入っていないこと）
2. 実機（縦持ちスマホ）で**全行が読み切れる**こと。3×でも行が間引かれて読めること
3. 実況が言った着差語と着順ボードの表記が**50本すべてで一致**すること
4. 同一レースを2回再生して**台本が完全に一致**すること（決定性）
5. 独走レース・大差レース・鼻先レースの3種で、それぞれ実況が別物になっていること
6. 予言の的中判定が、結果を先読みして選ばれていないこと（候補選択が入場時点の情報のみに依存していることをコードで確認）

**最も費用対効果が高い一点**：Phase 1 の「1行を短くして beat を可変にする」。総尺・行数・結果を一切変えずに、いま物理的に読めていない行を読める行に変える。これだけで体感の大半が変わり、以降のすべての施策の土台になる。
