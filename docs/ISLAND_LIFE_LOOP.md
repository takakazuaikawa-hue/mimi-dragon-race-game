# 好きな日常をつくる、中盤のおすすめ往復

## 本編への接続と実操作確認（2026-11-17）

`island_life_ui.js` がSNS・地図の現地・モール・食事の注文完了に接続する。第3話既読以降の任意の会話で、初見NEWと？を用意し、説明は通常閉じる。SNSでおすすめを選ぶと既存の場所へ移り、実食・実際の着替え・探索帰還を受けて感想を返せる。現地の通常表示は短い挨拶と「話の続きを」に留める。感想の後に元の位置で返信を見せ、次の訪問では前の話を覚えた挨拶へ切り替える。

既存の途切れも修正した。地図の写真から「ここで過ごす」で現地へ進める。料理クイズの正解後は、既存料金を明示して注文できる。正解だけでは実食・満腹・隠し席の開放にならない。自宅の通常料理は未食でも料理名と味の短文から選べる一方、発見料理と画像の解放条件は維持する。モールの圧縮探索で拾う薬のIDを実際に使えるIDに統一し、旧在庫は数量を保存して一度だけ移行する。圧縮探索のGは直接財布へ戻し、旧ワゴン残高も退出時に一度だけ精算する。通常探索の持ち帰り判断は保持する。SNSのバズ表示は既存反応式で到達可能な閾値へ修正したが、投稿本文の評価を作り直したものではない。

お気に入りの実体験一件を、終章の経済画面と任意の「最後の一面」試遊に表示する。`shingan_trial_bridge.js` が検証した `lifeMemory` だけを渡し、試遊結果には同じ人物・料理・場所の返事を出す。本編のEDを書き換える接続ではない。島を守る動機は報酬の得ではなく、自分がまた戻りたい日常として積み上げる。

GPT-6 Astraが隔離した第4話の画面を実操作し、塩パスタの注文→好みの返信→再訪、手持ちの服の無料着替え→別の好みの返信を確認した。その指摘から、返信がフィード末尾へ移動する問題、再訪に再実食を要求する問題、全店で同じ選択肢を常時出す問題を修正した。最終再確認でも、満腹のまま過去の一皿への感想を変えて財布・空腹が変わらないことを確認した。

親側の375px/1280pxブラウザ操作では、写真からの訪問、クイズと有料実食の区別、否定の感想と次の推薦、屋台のお気に入りと再訪、思い返し、無料着替えと保留、終章から試遊結果への思い出の継承まで通過。コンソール例外・HTTPエラー・横はみ出しなし、試遊前後の本編localStorage一致。`check_midgame_repairs.cjs` は実ソースをVMで呼ぶ11項目、`check_sns_engagement.cjs` は4項目を通過した。

これは章の状態を準備した試遊であり、自然進行での財布・空腹・解放時期を含む長時間の人間評価ではない。五つの遊びすべての深さや、長期的な島への愛着が完成したとは判定しない。新しい会話の相手も現状はアヤ一人であり、住民全員の日常を実装したものではない。

## 判断

中盤で島を守りたくなるには、終章に思い出の文章を足すだけでは足りない。遊んでいる間に「ここへ戻りたい」「前に話したことを覚えてくれている」と感じられる必要がある。今回の縦切りは、新しい収集ノルマや通貨ではなく、既存の食事・着替え・探索を試し、自分の好みを返すと次のおすすめと現地の迎え方が変わる一往復。

既存 SNS の常連アヤを使う。新しい関係本文は今回追加したもので、未実装だった過去の会話を既に体験したものとして補完しない。好感度点数、買い物回数の報酬、SNS への連投ボーナスは作らない。

## 最初の一周

1. アヤのおすすめに対し、今日の気分を一つ選ぶ。温かい一杯、静かな路地、装いを変えてモールへ。全て回る必要はない。
2. 元の画面で本当に行動する。食事は価格・満腹・食べられる条件が元どおり。服は手持ちへの無料着替えでもよい。モールは実際に歩く、戦闘を経験する、購入するなどの差分が必要で、入口から即退出するだけでは探索したことにしない。
3. 「またこれがいい」「わたしには別の方が合いそう」「まだ決めない」を返す。最初の二つに正解・不正解はない。お金や空腹の都合で体験できなかった場合は、そのまま見送れる。
4. 合っていたなら自分の好きな日常として一件残る。合わなかったなら別のおすすめへ変わる。SNS で返しても、現地で話してもよい。
5. 後で実際に現地へ戻ると、前の料理や服の話を覚えた返事がある。好きな店を変えても、保留しても、罰や損失はない。

ここで迷うのは「最大報酬の正解」ではなく、自分が求めた過ごし方に実体験が合っていたかと、次も同じ場所へ戻るか。アヤへ合わせる選択だけを良いものと扱わない。自分には合わなかった返事も、次のおすすめを変える有効な操作にする。

## 真実と門番

- `solveMeal` は料理の理解であり、実食ではない。新 module の meal event は、既存の実食処理が成功した後だけ通知する。以前の `eaten` フラグを見つけただけで、今回食べたと通知してはならない。
- 食べたことと店へ行ったことは別。`record({type:'visit'})` だけが実来訪を記録する。SNS で料理を気に入ってから初めて店へ行く場合、選択当時の履歴を遡って書き換えない。
- 温かい寄り道ではラーメンのほか焼き鳥／どて煮も選べるが、後者は勝ち飯横丁の一皿。負け飯屋台で食べたとは推論しない。本文におすすめの場所とは別の一皿を選んだことを明記する。
- `ura_bistro` の開放は既存の実食条件のまま。新ループは解除しない。未開放の隠し席へ visit event を送っても無視する。隠し席の画像は実際に開いた場所へ訪問した記録がある時だけ持ち帰る。
- 衣装は既存の所持情報を確認する。同じ服の再クリックは新しい着替えにしない。未所持衣装や `images/cg/*` を新ループから見せない。
- 競走・オッズ・配当・財布・報酬・読者数へ書き込まない。既存の買い物や食事はその元の処理が価格を扱い、この module は成功した事実だけを受け取る。

## 純粋 API

`js/island_life_loop.js` はブラウザで `IslandLifeLoop`、Node で CommonJS。DOM・時計・通信・本編 globals に依存せず、入力を変更しない。保存先は本編の専用 meta とし、親の adapter が保存する。

```js
ctx = {
  enabled: true, completedRaces: 12,
  openSpots: ['makemeshi', 'backbistro', 'mall'],
  ownedOutfits: [{id, name, image}], currentOutfitId,
  meals: [{id, name, eaten, image}],
  mallProgress: {steps, battles, purchases}
}
```

`openSpots`、所持服、料理の情報は既存の門番・台帳から作る。`mallProgress` は同じ基準の累積活動値を渡し、開始時との差分を判定する。新しい探索開始時にカウンタがリセットされる値を、そのまま累積値として渡さない。

| API | 内容 |
| --- | --- |
| `normalize(raw)` | version 1 の独立 meta を検証。日記に表示する会話履歴は 6 件、訪問足跡は対応する 4 地点まで。お気に入りと、各寄り道の最新会話 `conversations` 最大 3 件を別に残す。旧保存は履歴／お気に入りから復元し、新しい返事を優先する。 |
| `getView(raw,ctx)` | `{available,invitation,routes,active,history,arrivals,favorite,nextSuggestion,notice}`。行けない場所は候補から除外。`active.choices[].enabled` で未体験の好み断定を防ぐ。 |
| `start(raw,routeId,ctx)` | `warm` / `quiet` / `style`。開始時の所持服・着用服・探索活動を保存。同じおすすめを再度開いても baseline をリセットしない。 |
| `record(raw,event,ctx)` | 実際の native 操作成功を受ける。`visit` はおすすめ実行中でなくても記録し、後の再訪に反映する。 |
| `recall(raw,ctx)` | 同じ寄り道で保存されている過去の実体験を、今日の体験と区別して思い返す。`active.recallAvailable` / `recallLabel` が入口。未体験・別ルート・閉鎖中の場所では不可。料金・満腹・初食・訪問の event は発火しない。 |
| `respond(raw,opinion,channel,ctx)` | opinion は `again` / `different` / `unsure`、channel は `sns` / `in_person`。体験なしでも `unsure` は返せる。記録にない体験へ `again` / `different` は付けられない。 |
| `setAside(raw)` | いまのおすすめを中断。過去の好み・会話は維持し、期限や不利益を発生させない。 |
| `placeEcho(raw,spotId,ctx)` | 前の話を覚えた現地の短い返事。初回の文面は visit 記録前に取得し、その後 visit を保存して表示する。次の来訪では「おかえり」に変わる。 |
| `exportMemory(raw)` | 実体験を `again` とした最新のお気に入り一件を出力。保留だけの記録を終章の実体験に見せない。 |
| `normalizeMemory(snapshot)` | bridge で持ち込む専用記憶を検証。予想の手帖へ混ぜない。 |
| `finishEcho(snapshot)` | 同じ人・料理・服・場所を覚えた終章の短い返事。競走勝利や島救済の成否を捏造しない。 |

イベントは `{type:'visit',spotId}`、`{type:'meal',mealId}`、`{type:'outfit',outfitId}`、`{type:'purchase',outfitId}`、`{type:'mall_return'}`。meal はおすすめに関係する料理だけを受理する。探索帰りは開始時から 5 歩以上、戦闘 1 回以上、購入 1 件以上のいずれかを満たす必要がある。これは探索の事実確認であり、ポイント・ノルマ・好感度ではない。

`exportMemory` は `{version,id,routeId,placeId,placeName,image,person,handle,experience,opinion,channel,visited,visitedAtChoice,completedRace,outfit,quote,returnLine}`。`visitedAtChoice` は好みを返した時点、`visited` はその後の実来訪も含めた現在の事実。歴史を消さず、再訪によって今の関係が変わるよう分けている。

## 検証と残す問い

`rtk proxy node tools/check_island_life_loop.cjs` で、未実食・未所持・入口即退出の拒否、別料理の場所誤帰属防止、無料着替え、保留による退出、SNS 以外の返答、異なる好みによる次のおすすめ変更、初回と再訪、隠し場所の門番、過去履歴の不変、画像実在、6 件上限とお気に入り保全、報酬 CG の拒否を検証する。さらに、他の場所で 7 回返事をしても以前の好み／合わなかった返事を店が忘れないこと、最新の保留を古いお気に入りで上書きしないこと、旧保存の移行と各寄り道 1 件・最大 3 件の上限を検証する。

日記の表示枠と相手の記憶は別物として扱う。`history` から古い会話が消えても `placeEcho` は `conversations` を参照する。新しい会話でその場所の返事は更新されるが、別の場所で話すことを理由に忘れない。この会話保持の修正では公開 API の形を変えず、好感度・報酬も追加していない。

### 再訪で、食べ直さずに本音を返す

実操作で「違う気分でも聞かせて」と迎えたのに、新しい実食をしないと感想を返せないねじれが見つかった。再訪では、保存済みの同じ寄り道の実体験に限って「前の一皿を思い返して返す」を選べる。`experience.recalled=true` と元の `sourceOutingId` を entry／終章の snapshot に保持し、本文と返事でも思い返したことを明記する。後で本当に食べたり着替えたりすれば、通常 event が新しい実体験として置き換える。思い出を何度考え直しても元の実体験 ID は変えない。

これは空腹や価格の仕組みを無効にする無料の食事ではなく、既に味わったことについて考えを変える会話。未体験時は見送る／別の気分を選ぶ自由を示し、無効な感想ボタンを押すことを求めない。module の回帰は未体験と別ルートの拒否、元記録保持、再購入や実来訪の捏造なし、再考後の好み変更、snapshot の round trip を検証する。現地の初回判定は、UI が「挨拶を取得した」と「実訪問を保存した」を同一の cache flag にしていた断線を修正し、`in_person` だけから特定の店への訪問を推定して補完しない。

人が評価すべき点は、実際にその一皿や姿を選びたくなるか、好みに合わなかったことを言いやすいか、前の話を覚えている現地へ自発的に戻りたくなるか。分岐数や保存項目が増えただけで成功とは言わない。アヤ一人・三つの入口の小さな一周であり、住民全員の生活や五機能全体を作り直したわけではない。終章への接続は、ここで生まれた好きな日常を持ち込むことであって、中盤を終章用の収集作業にすることではない。
